# Довідник соціоніки

Інтерактивний довідник про 16 соціотипів, що працює за логікою І. Калінаускаса (чотири функції). Класична модель А — довідковий розділ. React, TypeScript, Tailwind CSS (Vite).

## Запуск

```bash
npm install
npm run dev      # розробка
npm run build    # збірка у dist/
npm test         # перевірки даних, аналізатора й інтерфейсу
```

## Структура даних (`src/data`)

| Файл | Зміст |
|---|---|
| `types.ts` | Типи TypeScript |
| `aspects.ts` | 8 інформаційних аспектів (Ne, Ni, Se, Si, Te, Ti, Fe, Fi) |
| `positions.ts` | 8 позицій моделі А: назва, блок, сила, опис |
| `sociotypes.ts` | 16 типів; модель А виводиться з базової й творчої функцій за правилом |
| `profiles/` | Профілі типів (12 розділів) |
| `kal/` | Основа сайту: 4 функції Калінаускаса, 8 аспектів × 4 функції × (10 тез (+) і 10 тез (−)), опис кожної клітини; `kModel` зіставляє функції 1–4 з позиціями моделі А 1, 2, 6, 5 |
| `theses/` | Тези за моделлю А (аспект × позиція). Не використовуються в інтерфейсі, збережені як довідкові |
| `contexts.ts`, `contextExamples.ts` | 5 контекстів спілкування та ситуативні приклади |

## Як рахуються тези

У Калінаускаса чотири функції. Для кожного типу сайт показує 4 аспекти × (10 тез (+) і 10 тез (−)) = 80 тез; для 16 типів — 1 280 показаних тез.
Унікальних клітин 8 аспектів × 4 функції = 32 (640 тез): типи з однаковим аспектом на однаковій функції діляться тезами.

## Джерела

Під кожним блоком є однослівна позначка «Джерело»: Калінаускас, Аугустінавічюте, Процький, Вікіпедія або Моє
(власне формулювання без прямого джерела). Пояснення — у підвалі сайту й у розділі «Про довідник».

## Перевірки

`npm test` перевіряє, що модель А кожного типу збігається з окремо введеною еталонною таблицею, що 16 комбінацій дихотомій дають 16 різних типів,
що в кожної функції рівно 10 + і 10 −, що немає дублікатів тез, і що весь основний сценарій працює в інтерфейсі.

## Аналіз повідомлень

Працює в браузері на правилах (ключові слова й тон), без мовної моделі й без запитів на сервер, тому секретних ключів немає.
Це евристика: вона не розуміє іронії та контексту. Числових оцінок вона не видає.

## Розгортання: GitHub + Cloudflare (Workers зі статичними файлами; чат і статистика)

Сайт — статична збірка (`dist/`) плюс серверний код у `worker/index.ts`, який використовує `functions/api/`: `chat` (чат із Claude), `theses` (тези під контекст спілкування), `event` (анонімні події), `stats` (підсумок подій).
Ключ API не потрапляє в код сайту: він зберігається як секрет у Cloudflare.

1. **GitHub.** Код у репозиторії; після кожного `git push` у `main` Cloudflare збирає й публікує сайт сам.
2. **Cloudflare.** Compute → Workers & Pages → Create application → Import a repository. Build command: `npm run build`, deploy command: `npx wrangler deploy` (значення за замовчуванням).
3. **Ключ API.** Створіть ключ на console.anthropic.com і додайте в проєкті: Settings → Variables and Secrets → тип Secret, назва `ANTHROPIC_API_KEY`. У Console задайте місячний ліміт витрат.
4. **Токен статистики.** Там само додайте Secret `STATS_TOKEN` (довгий випадковий рядок). Підсумок: `https://ВАШ-САЙТ/api/stats?token=ВАШ_ТОКЕН`.
5. **Сховище KV `USAGE`** створюється автоматично з `wrangler.toml`. Якщо деплой скаржиться на KV, створіть сховище вручну (Storage & databases → KV) і впишіть його `id` у `wrangler.toml`.
6. **Домен.** У проєкті: Settings → Domains & Routes → Add → Custom domain (домен має бути в Cloudflare).
7. Секрети діють після наступного деплою (Deployments → Retry або новий `git push`).

Тези під контекст (`/api/theses`) генеруються моделлю один раз для комбінації «аспект × функція × реакція × контекст» і кешуються в KV, тому повторні запити безкоштовні й миттєві. Без ключа або при збої сайт показує загальні тези.
Стан (тип, розділ, функція) зберігається в адресі `#tab=…&d=…&fn=…` і в localStorage: кнопка «Назад» і оновлення сторінки його не скидають.

Необов'язкові змінні: `THESES_LIMIT` (генерацій на IP за годину, 60); `CHAT_MODEL` (за замовчуванням `claude-sonnet-5-5`), `CHAT_LIMIT` (запитів на IP за годину, 20), `LOG_QUESTIONS=true` (зберігати текст питань у чаті; за замовчуванням лише довжина).

Що збирається: назви розділів, обрані типи й функції, факт запуску аналізу та чату. Тексти повідомлень для аналізу нікуди не надсилаються.
У локальному режимі (`npm run dev`) чат і статистика не працюють. Для перевірки з функціями: `npm run build && npx wrangler dev`.
